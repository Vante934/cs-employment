# 数据状态追踪：rebuild_all(force=True) 处理两个文件的情况

初始状态：
- 内存索引：[file1_old_vectors]
- 磁盘索引：[file1_old_vectors]
- SQLite：file1 chunks 标记为已索引

调用 rebuild_all(force=True)：

1. vector_index.clear()
   - 内存索引：[] (清空)
   - 磁盘索引：[file1_old_vectors] (未变)
   - SQLite：file1 chunks 仍标记为已索引

2. 处理 file2 (因为 list_files DESC 顺序)
   - build_index_for_file(file2, force=True)
   - 内存：添加 file2 向量
   - 第247行 save()：磁盘索引 = [file2] ← 覆盖！
   - 第259行 update_chunk_embeddings()：SQLite file2 标记为已索引

3. 处理 file1
   - build_index_for_file(file1, force=True)
   - 内存：添加 file1 向量 (现在有 [file2, file1])
   - 第247行 save()：磁盘索引 = [file2, file1] ← 覆盖！
   - 第259行 update_chunk_embeddings()：SQLite file1 标记为已索引

4. 最终 save() (第461行)
   - 内存索引：[file2, file1]
   - 这次 save 是冗余的，因为内存状态没变
   - 如果失败：磁盘仍是 [file2, file1]

状态总结：
- 成功时：磁盘和 SQLite 都包含所有文件 ✓
- 最终 save 失败时：磁盘和 SQLite 仍包含所有文件 ✓
- 中间 save 失败时：数据丢失，部分文件被覆盖 ✗
